# Номера документов и анализ извлечённого текста

## Диагностика браузера

В прежнем коде обзор зависел от текущего опубликованного индекса. Упоминание
имени PDF разрешалось только среди документов, прошедших эту проверку. При
нескольких подходящих документах чат предлагал вставить ссылку. Формулировка
«результаты моего анализа» могла попасть в общий ответ из-за отсутствующей
формы «моего» в правилах маршрутизации. Сравнение с референсами отдельным
сценарием также отсутствовало. Ручная остановка генерации штатно прерывает
ответ.

Эти причины подтверждаются исходным кодом. Чтобы проверить запущенную
версию, откройте авторизованный личный кабинет и выполните в консоли браузера.

```javascript
const response = await fetch("/api/documents?limit=1&sort=number&direction=asc");
const page = response.ok ? await response.json() : null;
const item = page?.items?.[0];
console.log({
  http: response.status,
  hasNumberField: item ? Number.isInteger(item.document_number) : null,
  extraction: item?.status,
  indexing: item?.index_status,
});
if (item) {
  const details = await fetch(`/api/documents/${item.id}`);
  const card = details.ok ? await details.json() : null;
  console.log({ http: details.status, version: card?.text_version?.version,
                locatorCount: card?.text_version?.locators?.length });
}
```

При непустом списке новая версия API возвращает `hasNumberField: true`.
Чтобы отдельно проверить совпадение имени загрузки и упоминание в тексте,
скачивание оригинала и покрытие Dense/Hybrid, используйте команды на чтение
из [HYBRID_RAG.md](HYBRID_RAG.md#диагностика-карточки-и-ссылки-из-извлечённого-текста).
Они не выводят извлечённый текст. Проверяйте источники самого чата на
синтетических документах.

### Если обзор не находит лабораторных записей

«Объясни результаты документа № 2» и «Сравни документы № 1 и № 2» до
исправления распознавались как нужные сценарии. При пустом результате
строгого разбора они завершались общим отказом, даже если извлечение
содержало видимый текст. В перечне словоформа совпадала со словарём и
показывалась как показатель без проверки числа и единицы.

Теперь при отсутствии подтверждённых измерений Qwen получает описание по
актуальным выдержкам. Сравнение по содержанию передаёт выдержки с номерами
документов. Ответ отдельно сообщает об отсутствии числового сопоставления.
Числовой режим выводит только проверенные записи и отмечает несовпадающие
единицы и отсутствующие показатели. В перечне отдельно показаны измерения
и упоминания. Если контекст урезан, перед ответом появляется «Частичный
обзор». Для описания резервируется место под служебный промпт и генерацию.
При отсутствии координат ссылка ведёт к общему блоку извлечённого текста.

Следующая проверка только на чтение. Она показывает для № 1 и № 2 статусы,
наличие актуального извлечения и числа локаторов и чанков. UUID владельца
возьмите из `/api/auth/me` в его авторизованной сессии. Используйте `dc`
уже работающего проекта.

```bash
read -r -p 'UUID владельца: ' owner_id
"${dc[@]}" exec -T postgres sh -c \
  'exec psql -X -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB" "$@"' \
  sh -v owner="$owner_id" <<'SQL'
BEGIN READ ONLY;
SELECT d.document_number, d.status AS document_status,
       coalesce(v.normalized_text ~ '[^[:space:]]', false) AS has_latest_extraction,
       coalesce(jsonb_array_length(v.locators), 0) AS locator_count,
       coalesce(j.status, 'not_indexed') AS index_status,
       (SELECT count(*) FROM rag_chunks AS c
        WHERE c.user_id = d.owner_id AND c.document_id = d.id
          AND c.text_version_id = v.id) AS chunk_count
FROM documents AS d
LEFT JOIN LATERAL (
  SELECT id, normalized_text, locators FROM document_text_versions
  WHERE document_id = d.id ORDER BY version DESC LIMIT 1
) AS v ON true
LEFT JOIN rag_index_jobs AS j
  ON j.text_version_id = v.id AND j.document_id = d.id AND j.user_id = d.owner_id
WHERE d.owner_id = :'owner'::uuid AND d.document_number IN (1, 2)
ORDER BY d.document_number;
ROLLBACK;
SQL
```

## Схема и сценарии

- UUID остаётся ключом документа. `documents.document_number` и
  `users.last_document_number` имеют тип BIGINT. Ограничение уникальности
  действует на пару «владелец, номер». Триггер внутри транзакции вставки
  увеличивает счётчик владельца и присваивает номер даже при вставке через
  старую версию приложения. Повтор запроса с тем же idempotency key возвращает
  существующий номер. Удаление документа не уменьшает счётчик.
- Миграция `0005_document_numbers` один раз записывает номера по
  `created_at, id` внутри аккаунта и инициализирует счётчики. Последующие
  сортировка, переиндексация и извлечение номера не меняют. Первичное
  распределение использует только записи, которые ещё существуют.
- Список ищет по номеру, имени или дате `ГГГГ-ММ-ДД` и сортирует весь
  отфильтрованный набор перед пагинацией. Дата отображается и фильтруется
  по Москве. UUID остаётся в ссылке на карточку и страницу источника.
- Чат разрешает номера только среди документов владельца. При нескольких
  подходящих документах он показывает номера и имена. Для сравнения
  надо указать номера всех документов. Номер отсутствующего или недоступного
  документа приводится в ответе, без подстановки другой карточки.
- Перечень известных показателей сканирует все доступные страницы и блоки
  извлечения. Краткий обзор использует выдержки, а ограниченный бюджетом
  ответ помечается как частичный. Обзор, разбор результатов и сравнение
  используют актуальный извлечённый текст PostgreSQL и его локаторы. Для них
  достаточно подтверждённого извлечения, в том числе при недоступном
  оригинале или отсутствии опубликованного векторного индекса.
- При разборе поддерживаются однозначные строки с показателем, числом,
  единицей и подписанным референсным интервалом. Пример синтетической записи
  `Калий: 5,8 ммоль/л (референс 3,5–5,1)`. Если интервал не распознан или
  его явно указанная единица отличается, в ответе указана неопределённость.
  Сравнение показывает исходные строки по каждому документу. Для двух
  документов отдельно сопоставляются однозначные пары одного показателя с
  совпадающей единицей. Разбор сохраняет исходные результаты и статусы
  относительно указанных интервалов. Неоднозначные таблицы и нераспознанные
  единицы требуют проверки извлечённого текста.
- Точные вопросы используют Dense/Hybrid, если выбранный документ имеет
  актуальный индекс. При его отсутствии проверяются записи выбранного
  извлечения. Перед выдачей ссылок сервер повторно сверяет владельца,
  версию текста и поколение для векторных попаданий. Общие вопросы по-прежнему
  генерирует Qwen без личного RAG.

## Формат PDF, проверка таблиц и контекст Qwen

PDF проходит проверку размера и контрольной суммы, затем локальный процесс
вызывает PyMuPDF 1.26.6 с `get_text("text", sort=True)`. Эта функция
имитирует расположение слов пробелами. Она возвращает обычный текст с
переносами строк. Детектор таблиц `find_tables()` и координаты слов в этом
пути не используются. PostgreSQL сохраняет полный полученный текст в
`document_text_versions.normalized_text`, если обработка уложилась в лимиты.
Для PDF локатор содержит номер страницы и символьные смещения в тексте.
Координат PDF-блоков и ячеек в сохранённой версии нет. DOCX сохраняет
смещения абзацев и строк таблиц. [PyMuPDF 1.26.6, get_sorted_text](https://github.com/pymupdf/PyMuPDF/blob/1.26.6/src/utils.py#L153) · [Page.find_tables](https://pymupdf.readthedocs.io/en/latest/page.html#Page.find_tables)

Обзор теперь распознаёт разделённые пробелами, табуляцией или вертикальной
чертой колонки из уже сохранённого извлечения. Нужны однозначные заголовки
названия, результата и единицы на той же странице. Референс учитывается
только из соответствующей ячейки той же строки. Названия в проверенной
таблице не ограничены словарём. Сопоставление между документами и проверка
интервала требуют распознанных единиц. Обычный поиск точных значений в чате
сохраняет свой строгий парсер.

Разорванные строки, объединившиеся колонки, сложные или неоднозначные
заголовки и сканы требуют отдельного разбора. Отсутствие распознанной
строки означает, что измерение не подтверждено текущим разбором. Если
макет в тексте утерян, для восстановления ячеек нужна геометрия оригинала
или OCR для скана. Изменение извлекателя и повторная обработка рабочих
документов этим выпуском не выполняются.

Прежний описательный обзор заполнял бюджет с первой страницы, а для
одного документа передавал строковые выдержки без номера. Это объясняет
смещение к шапке и давало модели возможность ошибиться при сопоставлении
номера с текстом. По одному ответу Qwen нельзя установить, как модель
интерпретировала фактический промпт в рабочей сессии.

Теперь отбор просматривает все доступные страницы, отдаёт приоритет
проверенным строкам и клиническим фрагментам и понижает приоритет общих
реквизитов. Документы получают отдельные доли бюджета. Каждый фрагмент
`document_context.fragments` содержит `document_number`, `page` или
`block` при наличии локатора и `text`. Модель получает признак `partial`.
Если генерация всё же утверждает, что переданный документ отсутствует,
сервер подставляет доступные выдержки вместо этого утверждения. Та же
подстановка применяется к числовым утверждениям в описательном ответе,
кроме номеров документов, страниц, блоков и пунктов списка. Описательный
ответ проверяется перед отправкой его текста клиенту.

Лимиты остаются прежними. По умолчанию `DOCUMENTS_MAX_PAGES=200`,
`DOCUMENTS_MAX_TEXT_CHARS=1000000`, `CHAT_CONTEXT_CHARS=2000`,
`LLM_CONTEXT_TOKENS=4096` и `LLM_MAX_TOKENS=1024`. У извлекателя есть
лимиты числа локаторов и времени обработки. Для описательного промпта
резервируются генерация, служебный текст и вопрос. Отбор считает байты
сериализованных фрагментов как консервативную оценку, без запуска
отдельного токенизатора. Это не измерение потребления RAM. Данные текущей
сессии, форматы конкретных PDF и значения рабочих настроек следует
сверять независимо.

Эффективные ограничения работающего backend можно получить без чтения
рабочего `.env` или вывода его содержимого.

```bash
"${dc[@]}" exec -T backend python -c '
from app.db import get_settings
s = get_settings()
for name in (
    "documents_max_pages", "documents_max_text_chars", "documents_processing_seconds",
    "chat_context_chars", "llm_context_tokens", "llm_max_tokens",
):
    print(name, getattr(s, name))
'
```

Проверка структуры сохранённого извлечения для № 1 и № 2 использует
только чтение. Она выводит идентификаторы, статусы, длины и счётчики без
имён файлов, реквизитов, лабораторных значений и текста. Подставьте UUID
владельца из `/api/auth/me` в его авторизованной сессии.

```bash
read -r -p 'UUID владельца: ' owner_id
"${dc[@]}" exec -T postgres sh -c \
  'exec psql -X -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB" "$@"' \
  sh -v owner="$owner_id" <<'SQL'
BEGIN READ ONLY;
SELECT d.id AS document_id, d.document_number, d.status,
       v.id AS text_version_id, v.version,
       coalesce(j.status, 'not_indexed') AS index_status,
       coalesce(char_length(v.normalized_text), 0) AS text_chars,
       shape.pages, shape.blocks, shape.page_chars,
       (SELECT count(*) FROM rag_chunks AS c
        WHERE c.user_id = d.owner_id AND c.document_id = d.id
          AND c.text_version_id = v.id) AS chunk_count
FROM documents AS d
LEFT JOIN LATERAL (
  SELECT id, version, normalized_text, locators FROM document_text_versions
  WHERE document_id = d.id ORDER BY version DESC LIMIT 1
) AS v ON true
LEFT JOIN rag_index_jobs AS j
  ON j.text_version_id = v.id AND j.document_id = d.id AND j.user_id = d.owner_id
CROSS JOIN LATERAL (
  SELECT count(*) FILTER (WHERE item->>'kind' = 'page') AS pages,
         count(*) FILTER (WHERE item->>'kind' <> 'page') AS blocks,
         coalesce(jsonb_agg(jsonb_build_object(
           'page', item->'index',
           'chars', (item->>'end')::int - (item->>'start')::int
         ) ORDER BY (item->>'index')::int)
         FILTER (WHERE item->>'kind' = 'page'), '[]'::jsonb) AS page_chars
  FROM jsonb_array_elements(coalesce(v.locators, '[]'::jsonb)) AS loc(item)
) AS shape
WHERE d.owner_id = :'owner'::uuid AND d.document_number IN (1, 2)
ORDER BY d.document_number;
ROLLBACK;
SQL
```

## Резервная копия, применение и откат

1. Завершите синтетические проверки. Убедитесь, что `dc` указывает на
   рабочий проект. Сохраните предыдущие образы и соответствующую копию
   исходников для dev bind mounts. Приостановите backend и worker на окно
   обслуживания. Сохраните PostgreSQL-дамп вне репозитория и Docker-томов.
   Проверьте восстановление копии на отдельном экземпляре.

   ```bash
   "${dc[@]}" stop backend worker
   read -r -p 'Путь к дампу вне репозитория: ' pg_copy
   "${dc[@]}" exec -T postgres sh -c \
     'exec pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > "$pg_copy"
   test -s "$pg_copy"
   "${dc[@]}" exec -T postgres pg_restore --list < "$pg_copy"
   ```

   Миграция изменяет PostgreSQL. Текущие резервные копии MinIO и Qdrant
   сохраните по штатному регламенту. Перестройка коллекций и backfill
   векторов для выпуска не требуются.

2. Соберите компоненты. На рабочем PostgreSQL проверьте исходную ревизию
   `0004_chat`, примените `0005_document_numbers` и повторно проверьте
   ревизию. Продолжайте только после успеха каждой команды.

   ```bash
   "${dc[@]}" build backend worker frontend
   "${dc[@]}" run --rm --no-deps backend alembic current
   "${dc[@]}" run --rm --no-deps backend alembic upgrade 0005_document_numbers
   "${dc[@]}" run --rm --no-deps backend alembic current
   "${dc[@]}" up -d --no-deps backend worker frontend
   ```

3. В браузере сверьте номера старых карточек, поиск, сортировки и ссылки.
   На двух синтетических отчётах проверьте «Что в документе № 1?»,
   «Перечисли показатели анализа 2», «Объясни результаты документа номер 2»,
   «Сравни документы № 1 и № 2» и запрос отсутствующего номера. Сверьте
   RU/EN-строки, числовые значения и интервал из каждой строки. Для отчёта
   с извлечённым текстом обзор должен быть доступен без скачивания оригинала.

4. При ошибке применения PostgreSQL откатывает транзакцию миграции. Сверьте
   ревизию до повторного запуска. Если миграция уже успешно применена, но
   проблема в приложении, остановите backend и worker и разверните сохранённые
   версии backend, worker и frontend с соответствующими исходниками для dev.
   Оставьте ревизию `0005_document_numbers`, чтобы сохранить выданные номера
   и новые записи. Триггер поддерживает загрузки из старого backend. В случае
   повреждения данных сначала восстановите дамп в отдельную среду и сверяйте
   новые записи перед любым восстановлением рабочего экземпляра.
